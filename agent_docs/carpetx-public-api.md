# CarpetX's public API

A thorn reaches CarpetX through two headers exported by `CarpetX/interface.ccl` from `CarpetX/src/include/`: `carpetx.hxx` for everything a general thorn needs, and `carpetx_rk.hxx` for the time integrator's opt-in RK contract. Every other header under `CarpetX/src/` is private: its first include is `internal.hxx`, whose `#ifndef CARPETX_INTERNAL` / `#error` is the one guard, and only CarpetX's own `src/make.code.defn` defines `CARPETX_INTERNAL`, so a translation unit of any other thorn that includes a private header by any path (the old exported name, `../../CarpetX/src/...`, `../../../CarpetX/CarpetX/src/...`) stops at that `#error`. The public headers include nothing under `CarpetX/src/`; if one ever did, every client would fail to build, so they cannot leak the driver's internals transitively.

`python3 scripts/boundary check` lists every `#include` outside `CarpetX/src/` whose path reaches into `CarpetX/src`, and every `CARPETX_INTERNAL` that is not CarpetX's own `make.code.defn` line or a private header's `#ifndef` guard. `check --since REV` reports only the lines added since the merge base with `REV`, which is what the `Comments` workflow runs on every PR. The whole-tree check is clean: no thorn in this repository includes a private CarpetX header, and `driver.hxx`, `schedule.hxx`, `reduction.hxx` and `timer.hxx` are no longer exported (`timer.hxx` no longer exists; `Timer` and `Interval` live in `carpetx.hxx`).

## Using the header

In `interface.ccl`, declare `USES INCLUDE HEADER: carpetx.hxx` (and `carpetx_rk.hxx` for an integrator); in `configuration.ccl`, `REQUIRES CarpetX` (the headers include AMReX, Loop and Arith headers, which that capability provides); in C++, `#include <carpetx.hxx>` or `<carpetx_rk.hxx>` and qualify every name with `CarpetX::`. The headers add no using-directive at any scope, so a client sees CarpetX names only when it names them.

A handle is a name made of indices, resolved on every call: `level_t{patch, level}` names a refinement level of a patch, `group_t{level, gi}` a grid-function group on it. A stale handle names a level that no longer exists and the call reports it with `CCTK_VERROR`; it never dereferences freed memory. `window_t{min_level, max_level, min_patch, max_patch}` names a set of levels, both for traversal and as the "which levels" argument of every operation; `active_window()` is the window the current traversal covers (a `CCTK_VERROR` outside a traversal) and `all_levels()` the whole hierarchy.

## The integrator's contract: `carpetx_rk.hxx`

Exactly one thorn, the time integrator, publishes what it integrates and reports the events of its RK step; CarpetX derives everything else. It registers once, `AT WRAGH`, with `register_integrator(rk_config_t{dense_output, b, integrated})`, where `dense_output` names the method whose dense output fills the refinement boundary under subcycling (`rk_dense_output_t::ssprk3`, `::rk4`, or `::none`), `b` holds the final-update weight of every RK stage (the method's `y1 = y0 + dt * sum_s b_s f(Y_s)`; one entry per stage, so `b.size()` is the stage count, and empty for an implicit method, which has no such weights and never feeds a flux register) and `integrated` holds `rk_pair_t{state_gi, rhs_gi}` pairs. CarpetX checks the record there, against its own parameters, and refuses: a second registration; a registration after the driver first read the record (`warn_inert_flux_tags`, right after PARAMCHECK, is the first reader, so anything later than WRAGH is too late); a `dense_output` whose method has another stage count than `b.size()` (`rk_dense_output_stages`); `dense_output = none` under `use_subcycling`; weights that are not finite or do not sum to 1 (all-zero weights are allowed for a method that never updates the state, such as ODESolvers' `constant`); an empty `b` under `do_reflux` with `max_num_levels > 1` when an integrated group carries a `fluxes=` tag; an integrated group that is not a grid function, is tagged `checkpoint="no"` or `evolve="no"`, is paired with a right-hand side of another size, or appears twice. A driver without a registration still runs (subcycling without an integrator, as before); only `open_rk_step` needs one, and it names it in its error. `TestCarpetXAPI/test/errors/` holds one expected-failure parfile per refusal.

The dense output is named, not inferred from the stage count: CarpetX's 3-stage table is SSPRK3's (AMReX `FillPatcher::fillRK`), so a different 3-stage method must register `none` and cannot run under subcycling. ODESolvers' `constant` method registers `rk4` with four zero weights, as it registered 4 stages before, so its buffers keep RK4's layout. ODESolvers' method table (`rk_methods.hxx`) holds every explicit method's weights, RKF78's eleven and DP87's thirteen included, and marks the IMEX rows implicit; `ODESolvers_InitConstants` registers the row's weights, or none for an implicit row.

|---|---|---|

| `CarpetX::max_num_rk_stages` from `driver.hxx` | none | the capacity of the driver's RK source bands; an integrator's stage count is the length of the weights `b` it registers |
| `*const_cast<CCTK_REAL *>(&cctkGH->cctk_time) = t; CallScheduleGroup(cctkGH, "G"); ... = t0` | `CarpetX::run_schedule_group_at(cctkGH, "G", t, delta_time)` | sets `cctk_time` and `cctk_delta_time` on the given cGH and on every driver cGH, traverses, restores both; `delta_time` is the raw `cctk_delta_time` the group sees (`CCTK_DELTA_TIME` divides it by `cctk_timefac`), so pass `cctkGH->cctk_delta_time` unless the step itself changes, as the IMEX half step does |
| `CarpetX::StoreRKOldState(patch, level, var_groups, tl)` on each level | `auto step = CarpetX::open_rk_step(window)` | one move-only `rk_step_t` per window and step, opened once the state holds u(t_n); on every level of the window it stores the old state of the registered pairs that have storage there and requires their interior valid; it must run outside an OpenMP parallel region; `CCTK_VERROR` without a registration |

| `CarpetX::Reflux(cctkGH, min_level, max_level)` | none | the RK step without subcycling, the driver under subcycling |
| `CarpetX::window_is_restricted(min_level, max_level)` | none | only the driver's recovery refill needed it |
| `CarpetX::group_is_integrated(gi)`, `group_has_flux_register(gi)` | none | the integrator knows its own groups; CarpetX answers these from the registration |
| `CarpetX::get_group_checkpoint_flag(gi)`, `get_group_evolve_flag(gi)` | none | `register_integrator` checks both tags of every integrated group |

Under subcycling the SYNC of an integrated group on a refined level at iteration > 0 copies only the same-level ghosts and requires the ghost bit to be set already: `state_updated`, or the driver's refill after a recovery, sets it. A SYNC that finds it unset is a `CCTK_VERROR` naming the rule, where it used to skip those ghosts silently and rely on the integrator to mark them. On level 0 the SYNC fills every ghost itself and marks them, as without subcycling. No thorn outside CarpetX sets a validity bit.
